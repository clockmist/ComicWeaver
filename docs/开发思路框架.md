# ComicWeaver 开发思路框架

## 1. 项目概述

### 1.1 项目定位
- **领域**: Agent + 图形学交叉应用
- **目标**: 基于多Agent协作的自动化2D漫画创作系统
- **周期**: 4周开发周期
- **团队**: 4人小组

### 1.2 核心价值
从简单的文本输入到完整漫画的端到端生成,降低漫画创作门槛,同时保持专业质量。

### 1.3 三种创作模式
1. **简单模式**: 主题 + 风格 → 自动创作完整漫画
2. **专业模式**: 详细剧本 → 高质量分镜漫画
3. **改编模式**: 小说/漫画原作 → 风格迁移创作

## 2. 系统架构设计

### 2.1 分层架构

```
┌─────────────────────────────────────────────────┐
│        交互反馈层 (Interactive UI)              │
│  实时进度 | 阶段确认 | 反馈输入 | 流式展示       │
├─────────────────────────────────────────────────┤
│       编排层 (LangGraph Workflow)               │
│  生产节点 → 审查节点 → 人机协作节点 → 下一阶段   │
├─────────────────────────────────────────────────┤
│              智能体层                           │
│  ┌──────────┬──────────┬──────────┐            │
│  │剧本理解  │角色管理  │分镜设计  │            │
│  │  Agent   │  Agent   │  Agent   │  生产Agent │
│  ├──────────┼──────────┼──────────┤            │
│  │图像生成  │排版合成  │          │            │
│  │  Agent   │  Agent   │          │            │
│  └──────────┴──────────┴──────────┘            │
│  ┌────────────────────────────────┐            │
│  │  审查Agent (Reviewer)          │  质量守门  │
│  │  格式校验 + 质量评分 + 返工决策  │            │
│  └────────────────────────────────┘            │
├─────────────────────────────────────────────────┤
│       模型层 (可插拔接口)                       │
│  SD/SDXL | DiffSensei | 云端API                │
├─────────────────────────────────────────────────┤
│       数据层 (SQLite + JSON)                    │
└─────────────────────────────────────────────────┘
```

### 2.2 核心Agent职责

> **Agent分类**:
> - **生产Agent** (5个): 负责实际产出内容
> - **审查Agent** (1个): 横向贯穿,审查所有生产Agent的输出

#### 剧本理解Agent
- **输入**: 用户Prompt/详细剧本/小说文本
- **输出**: 结构化场景描述JSON
- **核心能力**: 
  - 简单Prompt扩展为完整剧本
  - 长文本分段与场景识别
  - 叙事结构分析(起承转合)
  - 情感曲线提取

#### 角色管理Agent
- **输入**: 角色描述 + 历史参考图像
- **输出**: 角色档案 + 身份嵌入向量
- **核心能力**:
  - 角色视觉档案构建
  - CLIP特征提取与索引
  - 跨面板一致性追踪
  - 链式参考传递机制

#### 分镜设计Agent
- **输入**: 结构化场景 + 情感曲线
- **输出**: 分镜规划(景别/角度/布局)
- **核心能力**:
  - 视觉语法规则应用
  - 动态布局生成算法
  - 情感驱动的画幅分配
  - 阅读流优化

#### 图像生成Agent
- **输入**: 分镜描述 + 角色参考 + 风格参数
- **输出**: 单帧漫画图像
- **核心能力**:
  - 统一模型接口(UMI)抽象
  - 提示词工程与优化
  - 质量检查与重试机制
  - 多后端自动切换

#### 排版合成Agent
- **输入**: 单帧图像序列 + 对话文本
- **输出**: 完整漫画页面
- **核心能力**:
  - 自动画面拼接
  - 对话框智能放置
  - 文字渲染与排版
  - 多格式导出(PNG/PDF/PSD)

#### 审查Agent (Reviewer) ⭐ 新增
- **定位**: 质量守门人,横向贯穿所有生产环节
- **触发时机**: 每个生产Agent输出后自动触发
- **核心能力**:
  - **格式审查**: Pydantic Schema硬校验(失败必返工)
  - **质量评分**: LLM按rubric打分(0-10)
    - 剧本: 完整性、逻辑连贯性、情感曲线合理性
    - 角色: 描述具象度、视觉特征明确度
    - 分镜: 景别多样性、阅读流顺畅性
    - 图像: 角色一致性、与提示词匹配度
    - 排版: 对话框无遮挡、阅读顺序清晰
  - **决策输出**:
    - PASS (≥7分): 进入下一阶段
    - REVISE (4-7分): 携带问题清单返工生产Agent
    - ESCALATE (<4分或重试3次): 升级到用户决策
- **实现方式**: 复用主LLM,通过结构化prompt实现不同审查角色

## 3. 交互反馈机制 ⭐ 新增

### 3.1 设计哲学

借鉴 Claude Code 的交互模式:**让用户始终感觉"在驾驶座上"**,而非被动等待。

**三大原则**:
- **透明**: 实时展示Agent正在做什么、思考什么
- **可控**: 关键决策点暂停等用户确认
- **可逆**: 任何阶段可回退、调整、重试

### 3.2 交互模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 半自动 (默认) | 关键节点暂停确认,过程流式展示 | 大多数用户 |
| 全自动 | 全程不打断,仅错误时停止 | 批量生成、API调用 |
| 全交互 | 每个Agent输出都暂停 | 精细化创作、调试 |

### 3.3 关键确认节点(半自动模式)

```
用户输入
   ↓
[剧本理解Agent] → [审查Agent]
   ↓
🔔 确认点1: 剧本结构确认
   - 展示: 章节大纲、角色列表、情感曲线图
   - 操作: 接受 / 修改某场景 / 重新生成
   ↓
[角色管理Agent] → [审查Agent]
   ↓
🔔 确认点2: 角色设计确认
   - 展示: 每个角色的参考图(候选3张)
   - 操作: 选择 / 上传自定义参考图 / 调整描述重生
   ↓
[分镜设计Agent] → [审查Agent]
   ↓
🔔 确认点3: 分镜规划确认
   - 展示: 缩略图布局预览(无图像,仅框架+描述)
   - 操作: 接受 / 调整某页布局 / 增删页面
   ↓
[图像生成Agent] → [审查Agent] (循环N次)
   ↓
🔔 确认点4: 关键页审核 (可选,仅高质量模式)
   - 展示: 已生成的页面
   - 操作: 接受 / 重新生成某页 / 微调提示词
   ↓
[排版合成Agent] → [审查Agent]
   ↓
🔔 最终确认: 完整漫画审核
   - 展示: 完整漫画 + 导出选项
   - 操作: 导出 / 返工某页 / 保存项目
```

### 3.4 流式反馈展示

**实时展示内容**(无需用户操作):
- 当前执行的Agent名称与图标
- Agent的"思考过程"(LLM tokens流式输出)
- 进度条(基于状态机节点完成度)
- 中间产物预览(剧本JSON、分镜框图、缩略图)
- 审查Agent的评分与建议

**展示形式**:
- Gradio的 `gr.Chatbot` 组件展示Agent对话流
- `gr.Progress` 展示阶段进度
- `gr.Gallery` 实时追加生成的图像
- 折叠面板展示详细的JSON状态

### 3.5 审查反馈循环

```
生产Agent输出
   ↓
审查Agent评分
   ↓
   ├─ PASS (≥7分) ──→ 继续下一阶段
   │                    ↓
   │              [可选用户确认点]
   │
   ├─ REVISE (4-7分) ──→ 自动返工
   │                    ↓
   │              重试计数+1, ≤3次
   │              携带问题清单注入prompt
   │
   └─ ESCALATE (<4分 或 重试>3次)
                        ↓
                  🔔 升级到用户
                  展示: 失败原因、当前结果、可选项
                  操作: 强制接受 / 手动调整 / 跳过
```

## 7. 关键技术实现要点

### 7.1 角色一致性保障 (创新点1)

**链式参考机制**:
```
生成第N面板时:
  reference_window = [
    base_reference,        # 用户确认的基础参考
    panel[N-2].output,     # 倒数第二帧
    panel[N-1].output,     # 上一帧
  ]

  identity_embed = Σ(w_i × CLIP(f_i)) / Σw_i
  其中 w_i 按时间衰减(近期权重大)
```

**实现路径**:
1. 集成IP-Adapter作为基础参考机制
2. 实现CLIP特征提取与FAISS索引
3. 设计时间衰减权重函数
4. 角色档案动态更新策略(高质量帧入库)

### 7.2 情感曲线驱动布局 (创新点2)

**算法核心**:
```
情感强度 → 信息量指数 → 画幅分配
  高峰区域(>0.8): 大画幅、跨页布局、出血设计
  中等区域(0.4-0.8): 标准矩形格、3-4格/页
  低谷区域(<0.4): 小格、规整排列、6-9格/页
```

**实现路径**:
1. LLM输出每场景情感强度评分(0-1)
2. 情感曲线平滑处理
3. 布局模板库(矩形/斜切/出血/跨页)
4. 模板选择规则引擎

### 7.3 模型无关接口 (创新点3)

**统一抽象层(UMI)**:
```python
class ImageBackend(ABC):
    @abstractmethod
    def generate(
        self,
        prompt: str,
        negative_prompt: str,
        reference_images: list,
        control_params: dict,
        layout_info: dict
    ) -> GenerationResult:
        ...

    @abstractmethod
    def capabilities(self) -> dict:
        """声明后端能力(分辨率/控制方式/速度)"""
```

**实现路径**:
1. 定义标准化输入/输出schema
2. 实现SD/SDXL/DiffSensei/API四套适配器
3. 能力协商机制(根据需求选择最合适后端)
4. 自动降级策略(主后端失败→备用后端)

### 7.4 审查Agent实现 ⭐ 新增

**双层审查机制**:
```
第一层: 格式审查 (硬性)
  ├─ Pydantic Schema 校验
  ├─ 必填字段检查
  └─ 数据类型与约束检查
  失败 → 立即返工(不计入重试次数)

第二层: 质量审查 (软性)
  ├─ LLM按rubric评分(0-10)
  ├─ 维度化打分(完整性/连贯性/创意性)
  └─ 生成具体改进建议
  评分 → 决策路由
```

**Rubric示例(剧本审查)**:
```python
SCRIPT_RUBRIC = {
    "completeness": "场景信息是否完整(角色/地点/动作/对话)",
    "coherence": "前后场景是否逻辑连贯",
    "emotion_arc": "情感曲线是否合理(起伏、高潮)",
    "character_clarity": "角色身份是否明确无歧义",
    "visualizability": "描述是否可被图像生成模型理解",
}
# 每维0-10分,总分=平均分
```

**返工提示词注入**:
```python
revise_prompt = f"""
原始任务: {original_prompt}
你之前的输出存在以下问题:
{review.issues}
请针对性修正,特别关注:
{review.suggestions}
"""
```

**实现路径**:
1. 定义5种审查Rubric(对应5个生产Agent)
2. 实现审查决策器(PASS/REVISE/ESCALATE)
3. 重试策略(最多3次,递增温度参数)
4. 升级机制(生成用户友好的问题摘要)

```python
# 使用LangGraph的interrupt功能在确认点暂停
graph.add_node("checkpoint_script", checkpoint_node)
graph.add_conditional_edges(
    "checkpoint_script",
    lambda s: "continue" if s["user_decisions"][-1] == "accept"
              else "regenerate",
    {"continue": "character_agent", "regenerate": "script_agent"}
)
```

**流式输出适配**:
```python
# Agent内部使用LangChain的streaming callback
async def stream_agent_output(state):
    async for chunk in llm.astream(prompt):
        state["stream_messages"].append({
            "agent": "script",
            "type": "thinking",
            "content": chunk.content
        })
        yield state  # Gradio实时刷新
```

**交互模式切换**:
```python
def should_pause(state, checkpoint_name):
    mode = state["interaction_mode"]
    if mode == "full_auto":
        return False
    if mode == "full_interactive":
        return True
    # semi_auto: 仅在关键节点暂停
    return checkpoint_name in KEY_CHECKPOINTS
```

**实现路径**:
1. 定义5个标准确认节点(剧本/角色/分镜/关键页/最终)

3. Gradio事件处理(按钮回调→状态恢复)

## 10. 风险识别与应对

### 10.1 技术风险

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| GPU资源不足 | 阻断生成 | 准备云端API备用方案,提前申请AutoDL额度 |

| 风险 | 应对策略 |
|------|---------|
| 第一周架构未稳定 | 简化状态机,优先打通主路径 |

| 第三周集成困难 | 砍掉非核心功能(如改编模式) |
| 第四周报告时间紧 | W3末开始并行撰写报告大纲 |
